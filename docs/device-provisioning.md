# Provisioning устройств Khadas

Provisioning выполняется административной CLI backend с прямым доступом к PostgreSQL и не
публикуется как HTTP API. Перед использованием к базе должны быть применены миграции backend.
Команды ниже выполняются из каталога `backend`.

## Первичная регистрация

```bash
npm run device:provision -- --name "Кормушка на кухне"
```

Операция в одной транзакции создаёт устройство и его первые учётные данные. Успешный результат:

```json
{
  "device_id": "d6d174f4-e79f-49d1-9476-78bc99483752",
  "device_token": "dvc_<secret>"
}
```

`device_token` выводится только в этом ответе. В PostgreSQL сохраняются SHA-256-хеш полного
токена и короткий несекретный отпечаток, поэтому восстановить потерянный токен невозможно.

## Перевыпуск токена

```bash
npx tsx src/provisioning/device-provisioning.cli.ts rotate --device-id d6d174f4-e79f-49d1-9476-78bc99483752
```

Операция блокирует запись устройства, отзывает текущие активные учётные данные и создаёт новые
в одной транзакции. Новый `device_token` также выводится только один раз. Если транзакция не
завершилась, прежний токен остаётся активным.

## Отзыв токена

```bash
npx tsx src/provisioning/device-provisioning.cli.ts revoke --device-id d6d174f4-e79f-49d1-9476-78bc99483752
```

Первый отзыв возвращает `revoked: true`. Повторный вызов безопасен и возвращает
`revoked: false`. История учётных данных и само устройство не удаляются.

Вывод, содержащий `device_token`, нельзя перенаправлять в журнал, CI-лог или общедоступный
файл. После передачи токена на Khadas следует очистить сохранённый transcript или scrollback
терминала, если используемая среда их ведёт.
