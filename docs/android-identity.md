# Аутентификация Android-пользователя

## Учебный вариант

Android вручную получает пользовательский токен и передаёт его в каждом запросе:

```http
Authorization: Bearer usr_<secret>
```

`secret` состоит из 32 случайных байт в Base64 URL без заполнения. Токен не является JWT,
не содержит пользовательских данных и не требует внешнего OIDC-провайдера.

Backend хранит только SHA-256-хеш полного токена. Исходный токен нельзя прочитать из базы:
после создания он показывается пользователю один раз. Отозванный токен больше не принимается.

## Проверка доступа

После проверки токена backend получает внутренний `user_id` и отдельно проверяет активную связь
пользователя с `device_id` в таблице `user_devices`. Знание UUID кормушки не даёт доступа.

Для первой версии используются две роли:

| Действие | `owner` | `viewer` |
|---|:---:|:---:|
| Читать состояние кормушки | да | да |
| Читать расписания | да | да |
| Читать историю и детали кормлений | да | да |
| Создавать, изменять и удалять расписания | да | нет |
| Создавать команду ручного кормления | да | нет |

Первый владелец назначается административно. Токен устройства Khadas с префиксом `dvc_` не
может использоваться вместо пользовательского токена с префиксом `usr_`.

## Ответы backend

- `401 UNAUTHORIZED` — токен отсутствует, имеет неверный формат, неизвестен, отозван либо
  принадлежит заблокированному пользователю.
- `403 FORBIDDEN` — пользователь не связан с указанной кормушкой или его роль недостаточна.
- `404 NOT_FOUND` — ресурс не найден внутри устройства, доступ к которому уже подтверждён.

Обработчики используют `device_id` из проверенной связи пользователя с устройством, а не как
самостоятельное доказательство доступа.
