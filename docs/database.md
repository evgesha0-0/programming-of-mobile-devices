# Логическая модель данных PostgreSQL

Модель описывает централизованное хранилище backend. На Khadas PostgreSQL не требуется: Linux-приложение может использовать локальное файловое или встроенное хранилище для расписаний, обработанных идентификаторов и очереди неотправленных событий.

Все идентификаторы имеют тип UUID. Временные метки событий хранятся как `timestamptz` в UTC. Масса хранится как `numeric(8,2)` в граммах и должна быть положительной, если явно не указано иное.

## Реализация схемы

Начальная SQL-схема находится в `backend/migrations/001_initial_schema.sql`.
Команды запуска, правила добавления миграций и проверки описаны в `backend/README.md`.
Журнал `schema_migrations` хранит имена, контрольные суммы и время применения файлов.
Это служебная таблица, она не передаётся через REST API.

Составные внешние ключи дополнительно проверяют, что расписание или ручная команда
принадлежит тому же устройству, что и кормление, а `feeding_id` ручного результата
совпадает с идентификатором, назначенным командой. Мягко удалённые расписания сохраняются.
Триггер ручных команд запрещает изменение их идентификаторов, порции, времени создания
и срока действия, а также недопустимые переходы статуса.

Модель пользователей и авторизации, проверка IANA timezone, увеличение версии расписаний
и обработка конфликтующих повторов остаются задачами бизнес-логики backend.

## `devices` — устройства

Назначение: регистрация кормушки и хранение её последнего известного состояния.

| Поле | Тип | Обязательное | Ограничение / смысл |
|---|---|---:|---|
| `device_id` | `uuid` | да | PK |
| `name` | `varchar(100)` | да | отображаемое имя |
| `status` | `varchar(32)` | да | состояние устройства; значение по умолчанию `unknown` |
| `firmware_version` | `varchar(64)` | нет | версия Linux-приложения/прошивки |
| `last_seen_at` | `timestamptz` | нет | последнее принятое состояние |
| `schedule_revision` | `bigint` | да | неотрицательная монотонно растущая версия, по умолчанию `0` |
| `last_error_code` | `varchar(64)` | нет | последний код ошибки |
| `last_error_message` | `text` | нет | безопасное описание ошибки |
| `created_at` | `timestamptz` | да | время регистрации |
| `updated_at` | `timestamptz` | да | время изменения |

Учётные данные устройства не должны храниться в открытом виде. Схема хранения хеша секрета или ключей зависит от выбранного механизма авторизации и требует отдельного решения.

## `schedules` — расписания

Назначение: конфигурация автоматических кормлений, которую Android изменяет через backend, а Khadas получает для локального исполнения.

| Поле | Тип | Обязательное | Ограничение / смысл |
|---|---|---:|---|
| `schedule_id` | `uuid` | да | PK |
| `device_id` | `uuid` | да | FK → `devices.device_id` |
| `time_local` | `time` | да | локальное время кормления |
| `days_of_week` | `varchar(3)[]` | да | непустой набор уникальных значений `mon`…`sun` |
| `timezone` | `varchar(64)` | да | IANA timezone, например `Asia/Yekaterinburg` |
| `portion_grams` | `numeric(8,2)` | да | `> 0` |
| `active` | `boolean` | да | включено ли расписание |
| `revision` | `bigint` | да | версия изменения в пределах устройства |
| `created_at` | `timestamptz` | да | время создания |
| `updated_at` | `timestamptz` | да | время изменения |
| `deleted_at` | `timestamptz` | нет | признак мягкого удаления для синхронизации |

Связь: одно устройство имеет много расписаний. `UNIQUE(device_id, revision)` предотвращает неоднозначность версии изменения. Семантика `schedule_id` неизменна после создания. Backend увеличивает `devices.schedule_revision` при создании, изменении и удалении расписания.

## `feeding_commands` — команды ручного кормления

Назначение: надёжная очередь ручных команд от Android к Khadas.

| Поле | Тип | Обязательное | Ограничение / смысл |
|---|---|---:|---|
| `command_id` | `uuid` | да | PK; генерируется Android и обеспечивает идемпотентность |
| `feeding_id` | `uuid` | да | `UNIQUE`, идентификатор результата кормления |
| `device_id` | `uuid` | да | FK → `devices.device_id` |
| `portion_grams` | `numeric(8,2)` | да | `> 0` |
| `status` | `varchar(16)` | да | `pending`, `running`, `completed`, `failed` или `expired` |
| `created_at` | `timestamptz` | да | время постановки |
| `expires_at` | `timestamptz` | да | должно быть позже `created_at` |
| `started_at` | `timestamptz` | нет | заполняется при подтверждении Khadas |
| `finished_at` | `timestamptz` | нет | обязателен для конечного статуса |
| `error_code` | `varchar(64)` | нет | код ошибки для `failed` |

Связь: одно устройство имеет много команд. Переходы статуса должны быть монотонными: `pending` → `running` → `completed`/`failed`; `pending` → `expired`. Повторная вставка того же `command_id` не создаёт новую выдачу.

## `feedings` — события и результаты кормлений

Назначение: единая история ручных и запланированных кормлений.

| Поле | Тип | Обязательное | Ограничение / смысл |
|---|---|---:|---|
| `feeding_id` | `uuid` | да | PK; ключ идемпотентности события |
| `device_id` | `uuid` | да | FK → `devices.device_id` |
| `schedule_id` | `uuid` | нет | FK → `schedules.schedule_id`; только для `scheduled` |
| `command_id` | `uuid` | нет | FK → `feeding_commands.command_id`, `UNIQUE`; только для `manual` |
| `source` | `varchar(16)` | да | `manual` или `scheduled` |
| `portion_grams` | `numeric(8,2)` | да | целевая масса, `> 0` |
| `actual_grams` | `numeric(8,2)` | нет | измеренная масса, `>= 0` |
| `status` | `varchar(16)` | да | `pending`, `running`, `completed`, `failed` или `expired` |
| `created_at` | `timestamptz` | да | время создания события |
| `started_at` | `timestamptz` | нет | фактическое начало |
| `finished_at` | `timestamptz` | нет | завершение |
| `error_code` | `varchar(64)` | нет | машинный код ошибки |
| `error_message` | `text` | нет | безопасное описание |
| `received_at` | `timestamptz` | да | время приёма backend |

Проверки согласованности:

- для `source=manual` обязателен `command_id`, а `schedule_id` отсутствует;
- для `source=scheduled` обязателен `schedule_id`, а `command_id` отсутствует;
- для `completed` или `failed` обязателен `finished_at`;
- для `completed` обязателен `actual_grams`;
- `UNIQUE(feeding_id)` делает повторную отправку автономного события безопасной;
- внешние ключи на расписания должны допускать ссылки на мягко удалённые записи.

Для ручной команды backend может создать строку `feedings` одновременно с командой со статусом `pending`; итоговые измерения поступают только от Khadas.

## Источники данных

| Данные | Кто создаёт | Кто обновляет фактический результат |
|---|---|---|
| Устройство | backend при регистрации | Khadas отправляет состояние |
| Расписание | Android через backend | Android через backend; Khadas только читает |
| Ручная команда | Android через backend | Khadas подтверждает начало и присылает результат |
| Ручное кормление | backend при создании команды | Khadas |
| Запланированное кормление | Khadas | Khadas |

## Решения, требующие уточнения

- модель пользователей и привязки пользователей к устройствам;
- способ хранения и ротации учётных данных устройства;
- допустимые границы `portion_grams` и точность датчика;
- срок хранения истории и мягко удалённых расписаний;
- полный справочник состояний устройства и `error_code`;
- формат локального хранилища Linux-приложения.
