# Процесс параллельной разработки

## Ответственность веток

### `backend`

Сервер на TypeScript/NestJS, PostgreSQL, миграции базы данных, REST API, Docker и CI/CD.

### `linux`

Linux-приложение для Khadas на TypeScript/Node.js, интеграция с оборудованием, GPIO и датчиком веса, локальное выполнение расписаний, локальная очередь событий и взаимодействие с backend. Небольшой драйвер на C или C++ допускается только при подтверждённой аппаратной необходимости.

### `android`

Проект Android Studio на Java, пользовательский интерфейс, REST-клиент, настройка расписаний, ручное управление кормлением, состояние, история и уведомления.

### `dev`

Общая интеграция, согласованная документация и проверка совместимости компонентов. Контракт в [api.md](api.md) и модель в [database.md](database.md) синхронизируются здесь.

### `main`

Только проверенные стабильные версии проекта.

## Порядок интеграции

```text
рабочая ветка → Pull Request в dev → интеграционное тестирование → Pull Request из dev в main
```

1. Участник регулярно получает изменения `dev` в свою рабочую ветку без принудительного переписывания общей истории.
2. Изменения проходят локальные проверки и Pull Request в `dev`.
3. В `dev` выполняются сценарии из [testing.md](testing.md) и проверка совместимости контрактов.
4. После успешной интеграции создаётся Pull Request из `dev` в `main`.
5. Прямые коммиты в `main` не используются. Принудительный push в общие ветки запрещён.

## Правила совместной работы

- Каждый участник преимущественно изменяет директорию своего компонента.
- Изменение пути, метода, поля, типа, статуса или семантики общего API требует предварительного согласования и одновременного обновления документации.
- Изменения `dev` необходимо регулярно синхронизировать с `backend`, `linux` и `android`.
- Секреты, токены, пароли, приватные ключи, заполненные `.env` и реальные учётные данные нельзя добавлять в публичный репозиторий.
- Существенные промпты генеративных моделей сохраняются в `prompts/` или фиксируются в истории коммитов согласно требованиям преподавателя.
- Merge и rebase выполняются только в рамках согласованного командой процесса; эта документационная задача их не выполняет.

## Предлагаемая структура

```text
backend/   # в будущем: NestJS, БД, миграции, Docker
linux/     # в будущем: TypeScript-приложение Khadas и аппаратные адаптеры
android/   # в будущем: Android Studio, Java
docs/      # общая архитектура и контракты
prompts/   # существенные промпты без секретов
```

Каталоги компонентов приведены как целевая структура. На этапе подготовки документации фиктивная реализация и пустые каталоги компонентов не создаются.
